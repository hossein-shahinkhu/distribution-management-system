# سیستم مدیریت پخش کالا (Distribution Management System)

پروژه پایانی درس طراحی نرم‌افزار و پایگاه‌داده — دانشگاه قم

## معرفی

این سیستم برای مدیریت یکپارچه فرآیند فروش و پخش کالا طراحی شده است: از ثبت سفارش مشتری تا کسر خودکار موجودی انبار، صدور فاکتور، و تخصیص سفارش به توزیع‌کننده برای تحویل.

## معماری

```
distribution-management-system/
├── backend/     # Node.js + Express + PostgreSQL (Sequelize ORM)
└── frontend/    # React (Vite) + Tailwind CSS
```

معماری بک‌اند از الگوی لایه‌ای پیروی می‌کند:

```
Routes  →  Controllers  →  Models (Sequelize)  →  Database
                ↑
          Middleware (احراز هویت JWT + کنترل نقش)
```

جزئیات کامل معماری، نمودارها و روابط پایگاه‌داده در `ARCHITECTURE.md` آمده است.

## ماژول‌های پیاده‌سازی‌شده

- احراز هویت و کنترل دسترسی بر اساس نقش (ادمین، انباردار، فروشنده، توزیع‌کننده)
- مدیریت کالا، دسته‌بندی و موجودی انبار (با هشدار کمبود موجودی)
- مدیریت مشتریان
- ثبت سفارش با کسر تراکنشی موجودی انبار
- صدور فاکتور از روی سفارش
- مدیریت توزیع‌کنندگان و تخصیص سفارش برای تحویل
- گزارش‌گیری (فروش، انبار، عملکرد توزیع‌کنندگان)

قابلیت‌های فراتر از این دامنه (حسابداری کامل، حقوق و دستمزد، اپلیکیشن موبایل و...) به‌عنوان نقشه راه آینده در `ROADMAP.md` مستند شده‌اند.

## راه‌اندازی بک‌اند

```bash
cd backend
cp .env.example .env      # مقادیر دیتابیس و JWT_SECRET را تنظیم کنید
npm install
npm run migrate            # ساخت جداول دیتابیس (فقط بار اول و بعد از هر بروزرسانی کد)
npm run seed                # ایجاد نقش‌ها و کاربر ادمین پیش‌فرض
npm run dev                # اجرای سرور روی http://localhost:5000
```

کاربر ادمین پیش‌فرض پس از seed:
- ایمیل: `[email protected]`
- رمز عبور: `Admin@123`

⚠️ این رمز عبور فقط برای محیط توسعه است و باید بلافاصله در محیط واقعی تغییر کند.

## نکات امنیتی برای استفاده واقعی (Production)

قبل از استفاده واقعی و در دسترس‌قراردادن سیستم برای کاربران دیگر، حتماً این موارد را انجام دهید:

1. **رمز عبور ادمین پیش‌فرض را عوض کنید** — از دکمه «تغییر رمز عبور» در نوار بالای صفحه (روی نام کاربری کلیک کنید) یا مسیر API: `PATCH /api/auth/change-password`
2. **`JWT_SECRET` را به یک رشته تصادفی و طولانی (حداقل ۳۲ کاراکتر) تغییر دهید** — هرگز مقدار پیش‌فرض را در production استفاده نکنید.
3. **`NODE_ENV=production`** را در `.env` تنظیم کنید — این کار باعث می‌شود پیام‌های خطای فنی (stack trace) به کاربر نمایش داده نشود.
4. **`CORS_ORIGIN`** را به آدرس دقیق فرانت‌اند محدود کنید (نه `*`).
5. اگر دیتابیس روی سرور جدا میزبانی می‌شود، `DB_SSL=true` را فعال کنید.

سیستم به‌صورت پیش‌فرض دارای این لایه‌های امنیتی است:
- محدودسازی نرخ درخواست ورود (حداکثر ۱۰ تلاش در ۱۵ دقیقه) برای جلوگیری از حدس رمز عبور
- هدرهای امنیتی HTTP از طریق `helmet`
- اعتبارسنجی کامل ورودی‌ها در مسیرهای حساس (ثبت‌نام، ورود، کالا، مشتری، سفارش)
- رمزهای عبور با bcrypt هش می‌شوند و هرگز خام ذخیره نمی‌شوند

## مدیریت پایگاه‌داده (Migration)

از این نسخه به بعد، ساخت و تغییر جداول از طریق migration انجام می‌شود (نه `sequelize.sync()` که برای production ناامن است):

```bash
npm run migrate          # اعمال آخرین تغییرات پایگاه‌داده
npm run migrate:status   # مشاهده وضعیت migration ها
npm run migrate:undo     # بازگرداندن آخرین migration (برای عیب‌یابی)
```

هر بار که یک ویژگی جدید نیاز به تغییر ساختار جدول داشته باشد، یک migration جدید ساخته می‌شود؛ داده‌های موجود دست‌نخورده باقی می‌مانند.

## نقش‌های کاربری و دسترسی‌ها

| نقش | دسترسی‌ها |
|---|---|
| مدیر سیستم (admin) | دسترسی کامل به تمام ماژول‌ها |
| انباردار (warehouse_keeper) | مدیریت کالا، انبار و گزارش انبار |
| فروشنده (salesperson) | مدیریت مشتریان، ثبت سفارش، صدور فاکتور |
| توزیع‌کننده (distributor) | مشاهده و به‌روزرسانی وضعیت سفارش‌های تخصیص‌یافته |
